# 롤모델 개발 지침

롤모델은 캐스터 설계의 접촉·도막 손상·발열을 하나의 판정 흐름으로 설명하는 스크리닝 도구입니다. 인증 계산서나 FEM 대체재로 표현하지 않습니다. 간단 모드는 결론, 상세 모드는 물성·근거·유도 과정을 제공합니다.

## 변경 전 원칙

1. **근거를 등록한다.** 물리식은 `SRC`와 `CONF`로 출처·신뢰도를 표시합니다. 이론해, 설계기준, 근사, 경험식, 참고값, 보정값을 구분합니다. 출처 없는 경험계수를 새로 넣지 않습니다.
2. **경험값을 편집할 수 있게 한다.** 정책값은 실제 이론상수처럼 표현하지 않습니다. 검증되지 않은 기본값은 실측 확인 대상임을 표시합니다. 단부 완화·충격 상한·경고 구간 등은 상세 입력에 있습니다.
3. **판정에 이유를 붙인다.** 게이트는 `v`, `lim`, `s`, `why`, `rat: {expr, subs, src, note}`를 모두 가집니다. 식과 대입값은 실제 계산 분기에 맞아야 합니다.
4. **지원 범위를 넘으면 신고한다.** 가정이 성립하지 않는 결과를 종합 통과시키지 않습니다. 휠 들림·지지 불가능한 편심·충격 상한 초과·타원 후속 응력 모델 미지원·유한 폭 초과는 불가입니다. 단순 도막 분류는 전달압 항목이 따로 있어 주의 상한으로 유지합니다.
5. **근사의 방향과 불확실성을 밝힌다.** 도막/기재 반무한체 비교는 두 가정 중 높은 면압을 선택하지만 실제 층상체의 상한을 보장하지 않습니다. 출처 불명 두께 혼입식을 다시 넣지 않습니다.
6. **오프라인 단일 HTML을 유지한다.** 런타임 외부 라이브러리·프레임워크는 사용하지 않습니다. Google Fonts는 선택 사항이며 시스템 폰트로 동작해야 합니다. 빌드는 Node 내장 기능으로 소스를 결합합니다. Playwright는 개발 검증에만 사용합니다.

## 구조와 상태

```text
src/20_state.js       기본값·시나리오
src/30_engine.js      순수 물리 함수·재료·출처
src/25_validation.js  입력 및 설정 형식 검사
src/31_compute.js     계산 체인·게이트·제안·캘리브레이션
src/50_ui.js          DOM·SVG·입력 배선
src/60_guide.js       시작 가이드·별도 상태의 예시 계산
```

결합 순서는 `scripts/build.cjs`에 명시합니다. 엔진과 계산 함수는 DOM에 접근하지 않습니다. `S`가 상태의 유일한 진실이며, 재료 프리셋은 `applyWheel`/`applyFloor`로 상태에 복사한 후 사용합니다. 계산 중 `S`를 변형하지 않습니다. 재료의 이름·색은 표시 메타데이터로만 프리셋을 참조합니다.

입력을 추가하면 `DEFAULTS`, `validateState`, 필요한 `apply*`, `src/32_inputs.js`의 `INPUTS` 항목(라벨·단계 req/imp/exp·영향도·도움말·적용 조건)과 레일/스트립 배치를 함께 수정합니다. 영향도는 ±10% 재계산 근거로 정하며, 분류되지 않은 상태 키는 물리 검증의 배선 정합성 검사에서 실패합니다. 값 출처 `VSRC`는 계산 상태 `S`와 분리해 UI에서만 관리하므로 계산 결과에 영향을 주지 않습니다. 모든 숫자는 유한한 숫자로 검증합니다. 하중 배치 수는 정수 1~32이며 과도한 계산량을 제한합니다. 안전율을 작은 양수로 강제해 허용치를 부풀리거나 잘못된 치수를 조용히 보정하지 않습니다.

설정 불러오기는 `importState`로 임시 상태를 검증한 후 적용합니다. 실패 시 기존 상태와 화면을 보존합니다. 시나리오는 현재 간단/상세 모드와 탭을 유지합니다. 입력 오류가 발생하면 이전 결과·그림·내보내기를 지웁니다. 숫자 입력과 열 보정 입력은 매 렌더마다 재생성하지 않으며 포커스를 유지합니다.

## 계산 규약

`loadChain → 주행 하중 F_op → stepImpact → 피크 하중 F_pk → 접촉해 → 응력·열 → 게이트 → worst/driver → suggest` 순서입니다. 강도는 `F_pk`, 정상상태 열은 `F_op`로 검토합니다. 입력 오류나 접촉해 미수렴은 계산 거부입니다. `ok: true`는 계산 성공이며 설계 통과를 의미하지 않습니다.

길이는 mm, 힘은 N, 응력·탄성계수는 MPa, 속도는 m/s, 온도는 °C입니다. 열 계산에서 길이를 m로 환산합니다. 질량 표시에만 N을 중력가속도로 나눕니다. 섭씨 온도의 비율을 안전 여유로 사용하지 않습니다.

게이트는 하중 → 접촉 → 표면압 → 기재 → 전단 → 인장 → 열 순서로 배열합니다. 종합 판정은 모든 적용성 게이트를 포함하며 매트릭스·개선 제안도 같은 판정을 사용합니다. `bad`를 없애려고 기준을 완화하지 않습니다. 해당 없음이면 이유와 함께 `ok`를 표시합니다.

타원접촉의 `a`는 횡방향 반폭, `b`는 종방향 반폭입니다. 항상 `a ≥ b`인 것은 아닙니다. 곡률비를 정렬해 근사하고 원래 축으로 복원합니다. 후속 선접촉 모델을 타원에 그대로 쓰는 수치는 참고값이며 종합 불가로 차단합니다. 추가 구현은 독립적인 3D 기준해 검증을 먼저 준비해야 합니다.

모델 세부사항은 [MODEL-NOTES.md](MODEL-NOTES.md)를 따릅니다.

## 게이트·재료 추가

- 출처·신뢰도를 등록하고 임계값의 의미를 설명합니다. 사용자 정책 기준은 상세 입력과 검증 규약에 추가합니다.
- 수식 대조와 극한 또는 단조성 검증을 추가합니다. 모델 분기마다 식·대입·도면을 일치시킵니다.
- 재료는 `E, nu, tread, pa, ten, alpha, Tmax, kT, c`와 선택적인 정격점을 갖습니다. 정격점·손실률의 실제 제조사 근거가 없으면 검증된 카탈로그 값이라고 표현하지 않습니다.
- 프리셋을 바꿔 회귀 실패를 숨기지 않습니다. 가정이 강화돼 판정이 달라졌다면 근거와 새 기대값을 기록합니다.

## 화면과 성능

CSS 토큰을 사용하고 화이트 테마를 기본으로 유지합니다. SVG 치수·축척을 정직하게 표시하고, 720px 아래에서는 도면 배치를 다시 계산합니다. 텍스처 난수는 시드를 고정합니다. 기재 비교를 혼입률로 표시하거나 타원접촉을 직사각형 자국으로 표시하지 않습니다.

접촉 상세의 화살표는 국부 압력(MPa)을 길이로 표현합니다. 같은 재료·안전율에서 폭을 조절할 때 압력 눈금을 자동 정규화하지 않습니다. 축 상한을 넘으면 표시만 자르고 실제 수치와 초과 여부를 알립니다. 바닥 깊이는 잘라낸 도식이며 기재 두께 입력으로 해석하지 않습니다.

시작 가이드는 사용자의 S를 수정하지 않는 별도 예시로 설명합니다. 건너뛰기·다시 보기·키보드 Escape·포커스 복귀를 지원하고, 저장소 접근 실패를 허용합니다. 움직임 줄이기 설정에서는 애니메이션을 정지한 상태로 시작합니다. 안내의 재생·정지와 창 크기·키보드 접근성을 함께 검증합니다.

입력 그룹은 시나리오 → 하중 → 바퀴 → 바닥 → 주행 순서로 가이드와 번호·이름을 공유합니다. 메인 콘텐츠의 실제 너비가 960px 이상이면 왼쪽 입력·판정·계산 체인과 오른쪽 접촉 단면·접촉 자국을 병렬 배치합니다. 오른쪽 그림은 헤더 아래에 고정되며 높이가 부족하면 내부 스크롤로 모두 접근할 수 있습니다. 더 좁으면 입력 → 판정 → 그림 → 계산 체인 순서입니다. 모바일(960px 이하)은 상세 입력을 기본으로 숨기고 한 그룹씩 열며, 입력·결과 바로가기로 포커스와 스크롤을 함께 이동합니다. 데스크톱 사이드바의 상단 위치는 실제 헤더 높이를 따릅니다. 가이드에서 실제 설정으로 이동하면 설계 수치는 유지하고 필요 시 상세 모드만 열며, 가이드 재개 단계는 메모리에 보관합니다.

접촉 그림의 기본 SVG 표시 높이는 단면 320px, 자국 210px(좁은 화면 340/230px) 이하로 제한합니다. 큰 화면에서도 확대만 계속되지 않으며 핵심 수치는 HTML로 별도 표시합니다. 확대 대화상자는 SVG 복사본의 ID와 url 참조를 함께 변경해 원본 그라데이션·클리핑과 충돌하지 않게 합니다. 원본 그림, 압력 데이터 및 SVG 내보내기는 유지합니다. 확대·키보드·포커스 복귀·오류 시 비활성화와 360~2560px 양쪽 표시 모드는 `tests/visual-layout.cjs`에서 확인합니다.

상세 모드의 깊이 방향 응력과 표면 응력 분포도 오른쪽 시각화 영역에 포함합니다. 그래프 높이는 260px 이하이며 시각화 영역 폭 640px 이상에서는 두 응력 카드를 나란히 배치합니다. 시각화 카드의 flex-shrink를 해제해 높이가 부족해도 잘리지 않고 스크롤로 접근하게 합니다. 간단 모드에서는 응력 카드를 숨기고, 상세 모드에서는 선택한 분석 탭과 관계없이 비교할 수 있습니다.

정상 입력의 `compute()`는 1ms 수준을 목표로 합니다. 많은 재계산이 필요한 개선안은 입력이 멈춘 후 계산하고 최근 결과를 캐시합니다. 타이머·애니메이션은 입력 오류 시 취소하며, 이전 상태의 계산이 새 화면에 나타나지 않게 합니다. 역산·매트릭스·열 곡선은 해당 탭에서만 계산합니다.

## 빌드와 검증

```sh
npm run build
npm test
npm run test:ui
npm run build:check
```

`npm test`는 기존 물리 검증·36,000조합 스윕, 추가 결함 재현, 빌드·서버 검사를 포함합니다. `npm run test:ui`는 기존 스모크 항목, 실제 JSON/CSV/SVG 처리, 열 보정, 오류 회복, 9개 폭 및 모바일 상세 탭을 확인합니다. `layout-flow.cjs`는 입력·판정 순서, 하중 편집, 모바일 입력 접기·결과 이동, 가이드 6단계의 실제 설정 이동과 이어보기, 설계값 보존을 검증합니다. 실패는 반드시 비정상 종료코드를 반환합니다. 정의식을 그대로 반복하는 검사만으로 모델 정확성을 주장하지 않습니다.

고정 회귀 기준점: D80×L40, F=6343.83 N, 무도장 f_ck=30, E_c=30000 MPa 수동, 구속/층상 비교 OFF, K₀=1, 충격계수=1에서 **b=20.3635 mm, p_max=4.95814 MPa**를 유지합니다.

커밋에는 소스와 생성된 루트 `index.html`을 함께 포함합니다. 배포 생성물 `dist/`, 패키지 `node_modules/`, 검사 화면 `test-results/`는 Git에서 제외합니다. GitHub Actions는 기본 브랜치의 모든 검사가 통과해야 `dist/`를 Pages에 배포합니다. 문서·과거 보고서는 배포하지 않습니다.

## 후속 연구

반복 피로, 정차 크리프·압흔, 부분 슬립, 타원 접촉의 3D 응력·열, 축·베어링, 표면 거칠기, 프레임 동적 응답은 실측 데이터 또는 독립 기준해를 확보한 후 추가합니다. 이 기능들이 구현된 것으로 설명하지 않습니다.
