1원본 계산기에서 찾은 결함9건

가장 큰 문제는 개별 버그가 아니라 모델이 서 있는 자리였다. 원본은 두 물체를 모두 반무한체로 보는 고전 헤르츠 선접촉만 구현했는데, 주차로봇 캐스터는 그 가정이 성립하지 않는 조합(얇은 PU 트레드 + 박막 도막 + 좁은 폭)이 표준이다.

#결함결과
1휠 트레드를 반무한체로 가정 — 허브 접착 구속 무시 p_max 를 1.6~2.5배 과소평가
2표면 인장 σ_t 항목이 아예 없음 에폭시 균열·콘크리트 표층 박리의 실제 개시 응력을 못 봄
3마찰 하 최대전단 위치를 항상 0.786b 로 고정 μ > 0.30 이면 표면이 임계인데 엉뚱한 깊이를 지시
4단부 응력집중 없음 실제 파손이 시작되는 휠 폭 양 끝을 못 봄
5기재 전달압 없음 박막 도막에서 콘크리트가 받는 압력을 정량화 못 함
6크라운 반경 입력이 dead code 값을 넣어도 결과가 불변 — 사용자를 속임
7편심 모델이 휠 수와 무관하게 4점 고정 N = 6, 8 에서 분담률 오류
8동하중이 근거 없는 배수 (가감속·선회·단차를 임의 곱) 출처 없는 안전율 중첩
9속도·듀티·발열 개념 자체가 없음 PU 휠의 실제 정격을 결정하는 요인이 통째로 누락
①번이 왜 결정적인가 원본 조건(D80 × L40, 646.67 kg/캐스터)에서 구속 보정을 켜면 접촉 반폭이 20.36 → 12.44 mm 로 줄고 최대 접촉압이 4.96 → 8.12 MPa 로 오른다. 정확히 1.64배 과소평가였고, 이 조건에서는 허용치를 넘느냐 마느냐가 뒤집힌다.

2새로 도입한 모델출처 · 신뢰도 등급

모든 계수는 출처 대장에 등록하고 5단계 신뢰도를 화면에 노출한다. 출처를 댈 수 없는 계수는 코드에 넣지 않는다는 규칙을 세웠다 — 원본의 정체불명 상수 exp(−1.2·t/b) 가 이 규칙이 생긴 이유다.

트레드 허브 구속

S = b / t, x = 2k·S², M = E(1−ν) / ((1+ν)(1−2ν)) E_app = E + (M − E)·x / (x + (M − E)/E)

x→0 에서 Gent–Lindley E(1+2kS²), x→∞ 에서 구속탄성계수 M 으로 수렴하도록 보간했다. b 가 E_app 에 되먹임되므로 감쇠 고정점 반복(α = 0.35)으로 푼다. 근사 — Gent 형상계수의 검증 범위는 대략 S ≤ 2 (= t/b ≥ 0.5)이며, 게이트가 이를 감시한다.

표면 인장 — 균열 개시

σ_x(접촉 후단) = 2·μ_util·p_max f_ctm = 0.30·f_ck^(2/3)

마찰이 실리면 접촉 후단 표면에 인장이 생긴다. 에폭시 균열과 콘크리트 표층 박리가 실제로 시작되는 응력이며 원본에는 이 항목 자체가 없었다. 이론해 Johnson §7.1 · 설계기준 fib MC2010

마찰 하 최대전단 위치 전환

μ_util ≤ 0.30 → 표면 아래 0.786b 에서 τ = 0.300·p₀ μ_util > 0.30 → 접촉면 중앙(표면)에서 τ = μ·p₀

기동 조건에 따라 동원 마찰이 달라지므로 가용 마찰 μ 와 실제 동원 μ_util 을 분리했다. 직진은 a/g + f_roll(부분 슬립), 제자리 선회는 μ(완전 미끄럼). 이론해 Smith & Liu (1953)

단부 응력집중 · 기재 전달압

K_edge = 1 + (K₀ − 1) / (1 + 3·R_e/b) σ_z(t) = p_max / √(1 + (t/b)²)

단부는 실측·FEM 범위 K₀ = 2~3 을 쓰는 경험식이며 사용자가 조정한다. 기재 전달압은 선접촉 축상 수직응력 감쇠식으로, 이것이 있으니 "도막이 얇다"는 사실 자체로 설계를 죽이지 않고 결과를 정량 판정할 수 있게 됐다.

하중 체인 — 동하중을 등가편심으로

R_i = W·g·[ 1/n + e_x·x_i/Σx² + e_y·y_i/Σy² ]·k_flat e_dyn = (a/g)·h_cg ← 가감속·선회 하중이동은 편심과 수학적으로 동일

임의 N열 × M행 배치의 강체 탄성 분배로 일반화했다. 근거 없는 배수를 없애고 물리 입력(가속도, 무게중심 높이)으로 대체했다. 주행 F_op 와 단차 피크 F_pk 를 분리해 강도는 피크로, 발열은 연속으로 판정한다.

발열 — PU 휠의 진짜 정격

f = (4/3π)·α·(b/R) P = f·F·v·duty R_th = 1/(h·A + UA_hub) ΔT = P·R_th

열 기준 허용하중은 닫힌해 F(ΔT_a/ΔT)^(2/3) 를 씨앗으로 이분법 정밀화한다. 그리고 제조사 연속 정격점을 넣으면 α·R_th 를 그 점에 앵커하는 캘리브레이션을 넣었다 — 지어낸 계수 대신 실측에 고정할 수 있다. 근사 + 보정

5설계 방향일관성 규약

여러 사람이 여러 시점에 손대도 같은 방향으로 자라도록 원칙을 문서로 못박았다 (DEVELOPMENT.md).

  • 모든 숫자는 출처를 가진다 — 5단계 신뢰도(이론해 / 설계기준 / 근사 / 경험식 / 참고값)를 화면에 노출.
  • 경험값은 사용자가 바꿀 수 있어야 한다 — 하드코딩된 경험계수는 버그로 취급.
  • 판정에는 이유가 붙는다 — 게이트는 값 · 기준 · 왜 · 근거(수식/대입/출처/주석)를 모두 채운다.
  • 모르면 모른다고 한다 — 통과시키려고 가정을 느슨하게 만들지 않는다.
  • 안전측/비안전측 방향을 밝힌다 — 근사가 어느 쪽으로 기우는지 명시.
  • 단일 파일 · 무의존 · 오프라인 — 외부 라이브러리와 빌드 툴체인을 도입하지 않는다.

UI 는 계산 체인이 근간이다. 하중 → 접촉 → 표면압 → 기재전달 → 전단 → 인장 → 발열 순으로 실제 유도 순서대로 11개 검사가 세로로 흐르고, 각 행을 펼치면 수식과 근거가 나온다. 간단 모드는 결론, 상세 모드는 유도. 시각 언어는 IBM Plex 기반 기술 콘솔에 제도(製圖) 관습을 얹었다.

6남은 한계실무 영향 순
